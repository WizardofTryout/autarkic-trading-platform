# **Technical Specification: AI Trading Assistant (Live Execution Engine)**

Project: Autarkic Trading Platform  
Module: Automated Trading / "The Supervisor"  
Status: Draft / Specification  
Priority: High

## **1\. Overview & Objective**

We are building an **Automated Trading Assistant** that acts as an active portfolio manager. Unlike the "Research Agent" (which only analyzes), the Trading Assistant **executes trades** autonomously based on user-defined constraints and real-time market data.

Core Responsibility:  
Orchestrate the execution of generated Python strategies across multiple timeframes (MTF) while strictly adhering to Risk Management rules (Budget, Risk-to-Reward).  
**Key Logic:** "Trend Following with Local Entry."

* **Macro-View:** Analyze higher timeframe (e.g., 4h) for general direction (Long/Short).  
* **Micro-View:** Analyze lower timeframe (e.g., 5m/15m) for entry signals.  
* **Validation:** Execute only if the setup meets the user's Risk-to-Reward (RR) ratio.

## **2\. Architecture & Data Flow**

This module sits inside the backend or strategy-engine service and runs as a background task loop (using asyncio).

### **2.1 The "Supervisor" Class**

We need a new Python class TradingSupervisor that manages the lifecycle of an active trading session.

**Inputs (User Configuration):**

* **Global Budget:** Max USDT to allocate (e.g., 1000 USDT).  
* **Risk per Trade:** Max loss per trade (e.g., 1% of Budget).  
* **Target RR Ratio:** Minimum Risk-to-Reward (e.g., 1:2).  
* **Strategies:** Which generated python-strategies to use for signals.

**Data Flow:**

1. **Ingest:** Real-time WebSocket Data (OHLCV) for multiple TFs (e.g., 1h, 5m).  
2. **Analyze (Macro):** Run "Trend Strategy" on 1h data \-\> Output: BULLISH / BEARISH.  
3. **Analyze (Micro):** Run "Entry Strategy" on 5m data \-\> Output: SIGNAL\_LONG / SIGNAL\_SHORT.  
4. **Filter:** If Macro is BULLISH and Micro is SIGNAL\_SHORT \-\> **IGNORE** (Counter-trend).  
5. **Calc:** Calculate Position Size based on Stop Loss distance and Risk %.  
6. **Execute:** Send Order via OrderExecutionService.

## **3\. Database Schema Updates**

We need to persist the configuration of this agent.

**Table:** trading\_agents

CREATE TABLE trading\_agents (  
    id UUID PRIMARY KEY,  
    user\_id UUID REFERENCES users(id),  
    name VARCHAR(50),  
    status VARCHAR(20), \-- 'ACTIVE', 'PAUSED', 'STOPPED'  
      
    \-- Configuration  
    symbol VARCHAR(20), \-- 'BTC/USDT'  
    budget\_limit DECIMAL, \-- e.g., 1000.00  
    min\_rr\_ratio DECIMAL, \-- e.g., 2.0  
    risk\_percent DECIMAL, \-- e.g., 1.0 (1%)  
      
    \-- Strategy Links (The "Brain")  
    trend\_strategy\_id UUID REFERENCES strategies(id), \-- For Macro View (4h)  
    entry\_strategy\_id UUID REFERENCES strategies(id), \-- For Micro View (5m)  
      
    created\_at TIMESTAMP,  
    updated\_at TIMESTAMP  
);

## **4\. Functional Requirements (The Logic)**

### **4.1 Multi-Timeframe Analysis (MTF)**

The agent must hold data buffers for different timeframes.

* The system creates two DataFrame instances: df\_macro and df\_micro.  
* It executes the **Python Code** (generated by Strategy Builder) on both.
